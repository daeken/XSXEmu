# Compute dispatch correlation (owned only)

`compute_capture` consumes normalized observations. It does not hook retail code, parse opaque PSO arguments, or execute commands. The [producer trace](shader-binding-producer.md) identifies places to observe events; the [source join](compute-source-join.md) supplies static candidates, not live PSO identities.

- **Creation:** An observer must attribute a successful result to a non-reused PSO lifetime ID. Identify a program only after validating a bounded, complete code and launch-state snapshot in the same format/profile as a local catalog. `identify` compares complete code and launch bytes only when the format/profile, extent kind, relative executable start and known bounds agree. The result retains the catalog-scoped ID and non-byte span metadata, never infers an entry offset, and does not equate library IDs with wrapper IDs. Missing state, no match, or ambiguous matches stay explicit. No source digest, callsite, or object address substitutes for a program identity. The current static source join does not supply every needed creation input.
- **Recording:** Track one list lifetime at a time. Feed ordered pipeline/root/heap/table observations and call `gap` on reset, loss or an unhandled path that could change state. A root or heap snapshot replacement invalidates recorded tables. A pipeline event alone records an identity; it does not prove earlier root/heap state is compatible with that pipeline. Supply the independently verified root parameter for the question at hand, or explicitly leave it unknown. Lifetime IDs and bounded snapshots are the observer's responsibility; raw pointers are not lifetime IDs.
- **Dispatch:** Separate direct group counts from opaque indirect commands. Join to a still-live PSO record and preserve the provenance of one requested table base. A full-width observed handle can match only an exact stride boundary in a checked set of currently live GPU-side heap extents, with no overlaps. A truncated inline word never reconstructs high bits, even if only one plausible heap is present. The resulting slot range is not a descriptor payload decode, effective shader index, SGPR assignment, guest CPU mapping, or a claim of GPU execution.

## Table-base read receipt

`ListCapture::dispatch_at` retains the existing normalized `DispatchRecord` with an in-memory key (build-pinned observer session, list lifetime, dispatch occurrence). The observer must allocate non-reused keys and link an execution to the right recorded command; repeated execution of the same closed list does not reuse a key. No capture file or title format is defined here.

For one nonempty direct dispatch with an exact program match and a resolved table base, `validate_table_base_read` requires two additional checked observations: a live slot snapshot at consumption and the shader's actual scalar load. Both must refer to that occurrence. Check the root parameter independently proven to feed the user-SGPR, the heap generation, exact zero-extended address at the slot start, the full 16-byte span within that slot and all four consumed dwords. Equal addresses or words alone cannot supply missing provenance. The receipt retains only the occurrence and heap/slot identity; it does not validate resident entry, descriptor interpretation, store, or submission.

Tests: `cargo test --locked --offline --target x86_64-apple-darwin --test compute_capture --test shader_binding_capture`. The Win64 fixture records calls through an owned vtable and joins an exact-match code/state pair and the last table write to one bounded software load from owned bytes (no GPU). A separate Win64 test preserves a nonzero high word in the table handle. Negative tests cover identical dispatch records from different occurrences/sessions, absent or contradictory load evidence, wrong lifetime/root parameter, a short slot, a high-address lookalike, zero group count, and opaque indirect dispatch. The existing correlation tests also cover opaque/ambiguous identity, trace loss, root changes, retired lifetimes, truncated handles, conflicting heap geometry and arithmetic overflow.

A first live result still requires coordinated device and command-list observations, with the executed path identified (vtable versus inline; direct versus indirect), validation of the actual PSO creation payload, and live heap/lifetime and shader-side evidence. The [Scarlett submission candidate](scarlett-first-submission.md) is a separate observation boundary: even a verified list/token tuple does not witness shader execution. Report an incomplete record as incomplete rather than assuming an unobserved method or joining it to the nearest static candidate. Keep runtime artifacts local.
