# Native pixel interpolation: capture acceptance criteria

After the exact inline-zero PKRTZ change, the measured direct PS baseline is 233 encoding-complete windows and 223 attachment-only spans per +36/+40, wave32/wave64, gfx1013/gfx1030 hypothesis. The nearest unresolved interpolation cohorts are six contiguous windows requiring attr0 Y/W P1/P2 forms (only one needs just the Y pair) and three requiring attr0 MOV selector 2 (only one needs just X). A missing Y P1 at +40 in one window is a boundary/dataflow question, not evidence that P1 can be elided. See [owned graphics lift](owned-graphics-lift.md#pixel-blocker-ranking-after-dual-ba-recognition) for the operand breakdown.

AMD RDNA 2 ISA §§10.4.2 and 12.11 distinguish LDS parameter reads from ordinary LDS direct reads. MOV selector 2 reads P0; P1 uses P10 and P0 with its encoded coordinate source; P2 uses P20 and the old destination with its encoded coordinate source. For parameter reads the public M0 layout is `{0, new_prim_mask[15:1], lds_param_offset[15:0]}`. This is an ISA field description, not a translation of an Xbox launch SGPR to an LDS address or native producer slot. An explicit P0 buffer and center/no-perspective Metal varying are two different owned contracts; neither authenticates native coefficients.

## Evidence priority: static first, bound draw last

1. **Static instructions and def-use (highest confidence).** Under each checked entry hypothesis, recover exact attr/channel, MOV selector or P1/P2 coordinates and destination, and the last reaching writes to M0 and the P2 accumulator. Classify only reads that actually cross the candidate entry; retain the candidate in which Y P1 is absent at +40 as unresolved unless a reaching definition is proved. The reference CPU/wave matrix can disqualify a decode hypothesis; agreement cannot select the programmed entry or wave size.
2. **Static same-build correlation (candidate elimination).** Pin the build and pipeline revision, then intersect exact stage identities, body/extent candidates, source signatures, and checked native PARAM exports. Eliminate contradictory mappings and keep any ambiguity. A unique source pair or matching ordinal does not prove native routing, coefficient representation, or raster input mode. An authenticated same-build command/state record, if available, can establish the programmed entry, wave mode and linkage without repeating the draw, but only for the exact state generation it records.
3. **Bound-draw evidence (cannot be filled by static defaults).** Tie the programmed state to the executed shader and one primitive/lane. Observe the effective LDS record and coefficient bits with their representation: full versus packed/half layout where relevant, word/half selection, and any expansion before use. Record initial SGPR/VGPR/FP state only where an instruction consumes it before a proved local write. For MOV this means the live lane and parameter-read context, not unrelated entry VGPRs or FP mode. For P1/P2 it also means the used I/J values, the reaching old destination and effective FP mode; an accumulator proved local is a phase result, not an entry input. Stop if any consumed value cannot be tied to the same build, draw and lane.

## What to collect and how to join it

Start with one MOV-X-only witness and one Y-only P1/P2 witness. Use an authorized native capture or equivalent independently corroborated native evidence; a pre-submit emulator trace can establish which state was requested, not what the GPU loaded. Keep private payloads, addresses, raw traces, and identifiers local. For each evidence field record its source (directly observed, independently derived, or missing). No default on missing fields.

| Evidence | Minimum observation | What it establishes |
| --- | --- | --- |
| Draw and shader identity | One command submission/draw and pipeline generation; exact active producer stage and PS variants, authenticated code entry and extent, actual GPU revision and wave mode. Tie the executed PC to the exact bounded instruction; preserve +36/+40 as competing hypotheses until resolved. | Which variant and path the measurements apply to; joins by source signature or stage digest alone do not suffice. |
| Launch and M0 | Entry SGPR values used by the dominating M0 writer, its execution and effective M0 at each VINTRP, live EXEC/lane, primitive selection and LDS allocation/base/extent; record any later writers or relevant half-LDS mode. | The actual parameter-read context and its provenance, including whether different lanes use different primitive records. Ordinary LDS direct-read M0 type fields cannot substitute. |
| Producer and linkage | Effective producer PARAM export ordinal, component and mask with per-vertex raw words and clip position; actual native PS input routing to attr0, swizzle/packing, defaults when used, and per-vertex versus per-primitive source. Save topology, provoking vertex, primitive identity, vertex order and any clipping. | The route from the actual producer component to the consumer's parameter record. A DXBC signature register or PARAM ordinal cannot be presumed to equal the PS attr index. |
| Coefficients | For that lane/primitive/attribute/channel, capture the raw LDS P0/P10/P20 words and enough effective slot/offset/layout information to distinguish adjacent channels and primitive records. For MOV-only, proof of the selector and P0 word is sufficient for the load; controls must distinguish P0 from the other coefficients. If LDS is not visible, use a matched native reference that exposes the selected words and prove its pipeline, linkage, allocation and input invariance; a final color alone is insufficient. | The memory values actually consumed, not an interpolation fit inferred from final colors. |
| Coordinates and precision | For P1/P2, capture the encoded source VGPR values as raw bits for the same lane, the old destination at P2, and the P1/P2 result bits. Record input enable/address mapping, perspective/no-perspective, center/centroid/sample selection, sample ID/positions and helper/coverage status, plus effective FP mode and precision controls. | Which I/J pair was used, which P1 definition reaches P2, and which arithmetic the observed values support. MOV does not require I/J or FP arithmetic evidence to justify the read itself. |
| Observation identity | Correlate instruction state and result to the same draw, primitive, pixel/sample, wave and active lane. Prefer raw VGPR/word readback before color conversion; if using attachment readback, separately prove routing, format, write mask and coverage, and demonstrate the path preserves the tested distinction. | Prevents taking coefficients from one primitive and testing them against another, or hiding wrong results behind conversion or masks. |

## Discriminating captures and stop conditions

- Use distinguishable per-component and per-vertex values with P0, P10 and P20 different. For the MOV-X witness, hold the consumer and state fixed while changing only its producer input; vary an adjacent component separately as a negative control. Also sample another primitive with distinct values to check primitive selection. A constant-color or flat-data success is not evidence for the layout.
- For the Y pair, use an unclipped triangle with unequal clip W and gradients in both directions. Collect at least three noncollinear interior locations per primitive, with I and J different and both P10 and P20 observable. Independently change one producer component or one interpolation-state choice at a time. Check that swapped I/J, wrong channel or primitive, incorrect perspective or location, and substituting a different P2 accumulator all predict a different observation for at least one case. Center/centroid/sample distinctions require a sample configuration and edge coverage that actually distinguish them. Do not use a fixture's preselected mode to label an unknown native mode.
- Compare captured coefficients and coordinates against each instruction result before comparing final pixels. Restrict any first arithmetic claim to the captured finite domain and proven FP mode; if claiming fused vs split evaluation or denorm behavior, require a case that distinguishes it. For the inline-zero RTZ follow-on, the P2 result's domain remains a separate predicate, even when its source is linked correctly.
- Verify both exact bodies independently with LLVM reference CPUs and both disassembly wave settings, but label only the native observation as actual hardware/entry evidence. Report conflicts, unavailable fields, and negative results. If the capture cannot authenticate launch, select the correct LDS record, or associate native producer and consumer uniquely, keep that predicate unresolved. Recheck each additional channel, shape and start before extrapolating; one MOV-X or Y-pair capture does not close all nine windows.

This is a capture specification, not a capture or a decoder change. It makes no title PSO, translation, execution, or admission claim.
