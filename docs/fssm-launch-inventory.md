# FSSM compute launch-register inventory

The reachable census counts three observed GFX10 `COMPUTE_PGM_RSRC2` fields from the FSSM word at `+0x138`: `USER_SGPR[5:1]`, work-group ID enable bits `TGID_X/Y/Z_EN[9:7]`, and `TIDIG_COMP_CNT[12:11]`. The field map comes from AMD register semantics and the FSSM behavioural cross-check in Leonida `docs/design.md`. Counts do not identify the user-data values, buffer pointers, logical bindings or descriptor heap placement. No pipeline library data is read for this mode.

On LLVM 21.1.6 `gfx1013`, the small forward-only wave32 shortlist has 18 complete graphs; user-SGPR counts span 4–11. Seventeen enable only X group ID with a single local-ID component; one enables X/Y with two components. The two `1×1×1` single-raw-store candidates each enable only X with a single local-ID component, and request five and six user SGPRs respectively. In the smallest (10-node) graph, the feature census sees one scalar-memory instruction, one wait/cache instruction, and one vector-buffer instruction. There is no reachable branch or compare indicator in this graph. The combined owned EXEC/store test is therefore useful for the *wider* shortlist, not a claim that it models this smallest candidate.

The immediate retail blocker is the **meaning and provenance** of those launch inputs. Confirm which live-in SGPR pairs supply descriptor-table addressing; join that evidence to independently verified binding metadata or captured owned dispatch setup. Neither an SGPR count nor a successful static decode establishes safe host resource bindings. Keep exact raw buffer layout and interpreter/Metal equivalence separate from the synthetic fixture.

## Descriptor-base provenance

`--reachable-compute` now follows ordinary SGPR values for the small single-raw-store candidates when the complete reachable stream also forms a straight-line, finite program. It accepts a limited set of LLVM mnemonics, tracks scalar moves, distinguishes entry user data from other entry registers, tracks all four words of each scalar descriptor load, and requires that the exact modeled `lgkmcnt(0)` wait precede the raw store. Unsupported encodings, writes, operands or control flow report an unsupported provenance classification instead of guessing. This computes only the origin of the store's descriptor load, not all data or synchronization dependencies. No operand or payload identity is emitted.

Under explicit LLVM 21.1.6 `gfx1013`, **2/2** shortlisted raw-store programs load the store descriptor from a base built by zero-extending one user-data SGPR. Both preserve the descriptor as one four-word load until use. This is static evidence for a 32-bit input value forming a zero-extended address, not evidence that it is a particular heap base, root descriptor table, or host pointer. The outstanding requirement is external confirmation of the concrete root binding and address-space mapping (including range and lifetime) before Metal binding or any dispatch. The independently compiled library variant still cannot be selected solely from this result.
