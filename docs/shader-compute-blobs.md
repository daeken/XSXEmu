# Expanded PS/0/9 compute blob shapes

`cargo run --locked --release --manifest-path tools/shader-inventory/Cargo.toml -- --compute-blobs /path/to/local/library.bin` first runs the structural index checks, then reads the bounded blob section (64 MiB maximum), not the program code. It interprets only the three blob references in each compute row; it does not use the extraction's JSON indexes, link source shader digests, or recover bindings. The field hypotheses come from Leonida `docs/fspx.md` and `docs/shader_library.md`; the counts below are independent checks on this extraction.

| Compute row reference | Checked shape / fields |
|---|---|
| `+0x08`, dispatch | Exactly 28 bytes. Word 3 packs `X` in bits 0–15 and `Y` in bits 16–31; word 4 packs `Z` in bits 0–15 and the observed wave32 flag at bit 20. Require a positive product at most 1,024. Words 5/6 are kept as observed mode/resource words; the `COMPUTE_PGM_RSRC2` interpretation of word 6 is used for scratch bit 0, group-size input bit 10 and LDS allocation bits 15–23. Words 0–2 and the rest of word 4 are not interpreted. |
| `+0x0c`, opaque | Exactly 20 bytes; no type tag or semantic interpretation is assumed. |
| `+0x14`, layout | 24-byte head (exact u32 `0x403` at `+0x00` and low-byte tag `0x40` at `+0x14`), then zero or more 32-byte items with exact u32 tag `0x41` or `0x42`, then a 32-byte trailer (u32 `0x43`, 16 uninterpreted bytes, 12 zero bytes). No descriptor payload, digest or binding is printed or interpreted. |

All **2,693** compute rows passed, referencing **665** unique dispatch blobs, **2,684** opaque blobs, **2,684** layouts and **2,684** programs. The modeled dispatch fields do not disagree across rows referencing the same program. At row granularity there are **1,535 wave32**, **1,158 wave64**, **91 group-size input**, **480 nonzero LDS**, and **zero scratch-enabled** entries. At program granularity **1,529** have the wave32 flag and **91** have the group-size input bit in this local extraction. Counts are distinct from FSSM and should not be transferred from one representation to the other. Layout items (including repeated layout references) total **98,806 tag `0x41`** and **92,987 tag `0x42`**, with up to **328 items** in one layout.

The host-independent `xsxemu::compute_metadata::ComputeMetadata::from_library` consumes already checked `PipelineLibrary` blob spans; the bounded auditing tool shares the same leaf validators. An owned fixture tests exact field locations, truncation, group limit and malformed tags/trailer. The audit does not prove dispatch, layout semantics, or a GPU binding. The next ABI gap is connecting item records and actual per-stage user-data inputs to validated root signatures and live descriptor mappings; an in-range table index is not evidence of a valid Metal resource assignment.
