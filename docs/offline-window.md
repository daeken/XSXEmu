# Trusted-offline window creation

This is a bounded startup contract, not a User32 provider. Direct root imports of `RegisterClassExA`, `CreateWindowExA`, and `DefWindowProcA` on the NTUSER window ANSI API set are private to trusted-offline startup with Rust providers. No DLL aliases, forwarded exports, or dynamic discovery are added.

`CreateWindowExA` accepts the observed overlapped top-level call shape: no extended styles, parent, menu or parameter; default x/y; explicit positive sizes up to 8192; and bounded ASCII class/title strings. It resolves the owned ANSI class by name and guest instance, and checks its immutable guest callback against the active CFG policy, if enabled. No callback or host allocation occurs for a rejected input. The AppKit backend treats dimensions as content dimensions, centers the window, and deliberately omits close/minimize controls; Win32 nonclient geometry is not modeled.

The process main thread alone creates and owns the `NSWindow`; when creation is bound, PE startup runs on a dedicated thread. Creation and completion requests cross a private host channel. The guest handle is a process-local key, never an Objective-C pointer. Creation calls `WM_NCCREATE` and then `WM_CREATE` synchronously on the originating guest thread, with a temporary Win64 `CREATESTRUCTA` and checked GS/TEB handoff. `DefWindowProcA` is defined only for that active pair, with an explicit terminal diagnostic for anything else. A zero `WM_NCCREATE` or `-1` `WM_CREATE` rolls back the host object and invalidates the provisional guest handle. The backend confirms the window is hidden, not key, and not main before committing the handle.

There is no activation, ordering, event pump, or AppKit-to-guest callback. `ShowWindow` remains unresolved on the neutral window API set. Win32 message queues, general dispatch, destruction/lifecycle messages, input, presentation, and GPU device creation remain outside this contract. Host objects are dropped on the main thread at normal guest shutdown. An owned Rosetta PE exercises the actual AppKit backend in a WindowServer session; the CFG-denial test needs no WindowServer.
