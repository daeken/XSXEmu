# Scarlett first direct queue: device slot 8

Static caller evidence from the same pinned AMD64 title image as the [startup ABI map](xbox-d3d12-abi.md) (`e95020b2fa4a721db3df59fdecf75621730ac559d8835252f6c3b658d5a08993`). Addresses below are RVAs; add `0x140000000` for the preferred disassembly address. No native device call was executed for this audit. “Direct queue” is the best-fit public interpretation of the observed descriptor, not a claim of full desktop parity.

## First creation call and lifetime

| Evidence | Observed caller contract |
| --- | --- |
| `0247875e`, `02478783` | Loads 16 bytes from image constant `0615b0b0` and overwrites the prior slot-26 scratch at `rsp+0xd0`. Bytes: `00 00 00 00  00 00 00 00  00 00 00 00  01 00 00 00` (four little-endian dwords `0,0,0,1`). All 16 bytes originate in the constant, not in slot 26 or in device creation parameters. No extension tail is initialized as part of this argument. |
| `02478766`–`0247878a` | `RCX=*08759d00` (created device; see store at `02478621`); `RDX=&[rsp+0xd0]`; `R8=&061e0648` (IID `0ec870a6-5d7e-4c22-8cfc-5baae07616ed`); `R9=&08759ff8` (writable pointer slot in title global storage). Loads vtable via `RCX`, calls `[vtable+0x40]` (zero-based slot 8); no fifth argument is set up. |
| `0247878d`–`024787d0` | Saves `EAX`, passes it to a status helper, then branches on the saved sign. Negative status calls **device** slot 2 at `024787a4` and returns zero from the enclosing routine. The caller neither loads nor releases the queue on this edge and does not explicitly clear the queue global at the callsite. This is not evidence of how the native callee writes the output on failure. |
| `024787d1`–`024787e7`, `05a86180`–`05a861aa` | Nonnegative status loads the queue global without a null check and passes that value in `RDX` to a title wrapper initializer (`RCX=&075e0e98`, `R8D=0`). The helper first creates a fence-shaped object via device #36 (`01d0b2fa`, fence IID at `061e0618`); only when it returns a non-null object does it store the queue at wrapper `+0`. That store has no observed queue `AddRef` on this path. No queue vtable dispatch in the immediate success sequence before the first slot-48 queue creation. The scratch prefix is overwritten again at `0247880c`, excluding deferred borrowing of that original 16-byte payload by a conforming implementation. |
| `0248bcba`–`0248bcc4` | Later cleanup loads the direct queue global and invokes queue slot 2 (`+0x10`) without a null test at that site, then releases the four adjacent slot-48 queue outputs. This is consistent with the caller holding a queue reference and the initializer aliasing it; it does not prove internal device retention, exact refcounts at every stage, or a contract for arbitrary IID, retry or aliasing. |

## Comparison and ring boundary

The pinned desktop [DirectX-Headers `d3d12.h`](https://github.com/microsoft/DirectX-Headers/blob/75edcf75f4c0942dd0d39e75fdc5c42ca6f285fd/include/directx/d3d12.h) has device #8 `CreateCommandQueue` and the same queue IID. The observed words match desktop `DIRECT`, normal priority, no flags, and node mask `1`. The descriptor prefix and requested IID do not authorize forwarding to a desktop queue vtable; the observed queue #18 already disagrees. Leonida's GPL `docs/retail_boot_chain.md` §3.2 likewise reports the first queue at device #8, and subsequent queues at #48; its proxy behavior is not a native contract. XCL's GPL `HANDOFF.md` (Unicorn Overlord bring-up, `91f9a5e`) reports one queue revision with frequency at #18 and a presentation extension at #32, versus #16/#30 in an older layout, despite the same device SDK version word. Use those as comparisons, not bindings or proof of the remaining slots.

The likely 1 MiB graphics-ring request is in **device creation** (`+0x08`), not any of the 16 bytes supplied to #8; no base or explicit size argument is passed here. See [device creation evidence](scarlett-device-creation-evidence.md). Slot 8 may depend on device-held state, but the caller does not reveal when native ring reservation/materialization happens, its backing/registration requirements, or its interaction with unresolved device flag `0x20`. A host Metal command queue, a matching byte allocation, or an owned publication test cannot resolve them. The queue scratch evidence likewise cannot justify reading beyond 16 bytes. Resolving the native creation/ring contract needs documentation for the matching GXDK or a controlled original native sample that varies the request and observes allocation/status at device creation, direct queue creation, and first submission separately.

## Bounded owned fixture (not runtime admission)

`cargo test --offline --locked --target x86_64-apple-darwin --test xbox_direct_queue_abi` runs the owned assembly caller with a local synthetic device vtable. It dispatches `+0x40` with independent Win64 register setup: the exact observed 16-byte tuple ends at a guard page, the public queue IID is in separate storage, and canaries enclose the output pointer. The synthetic callee checks argument identities and exact bytes before staging anything. Tests reject a null output, a mutated descriptor, and a mutated IID without staging or publishing a queue. It stages a single queue reference and can refuse before publication; the caller checks signed status and releases only the device on refusal. Nonzero positive status exercises success: the wrapper borrows the queue pointer, the caller overwrites its scratch, and queue slot 2 destroys the one published owner. Both paths verify exact teardown counts and unchanged output canaries. This is a Mach-O test of Win64 transport and an owned lifetime policy, not a native Xbox failure contract, a PE boundary test, a slot-18 fixture, or evidence about graphics rings. No provider, SDK DLL or title execution is needed.
