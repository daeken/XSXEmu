# Title-addressed descriptor heaps: test-only model

This model asks a bookkeeping question: **if the caller already has a guest virtual address for a descriptor heap, can the model preserve that address and reject invalid or stale slot references?** It does not implement any Xbox D3D12 method.

## Evidence and limits

- Leonida's `docs/retail_boot_chain.md`, step 13, reports that a retail caller reads the slot-9 return value from RAX and compares it to an address it already holds after its first `CreateDescriptorHeap` call. The report treats the provenance of the expected address as a hypothesis. Its `docs/d3d12_command_objects.md` §4.2 attributes the slot-9/10 RAX return convention to the earlier `americas-recomp` probe. The return convention does not establish any relationship between the CPU and GPU handle values.
- XCL's [`HANDOFF.md` retail bring-up notes](https://github.com/ivall/xcl/blob/91f9a5e/HANDOFF.md#retail-game-bring-up-2026-11-23) report using title `__XMemAllocationHooks__` to obtain descriptor heap memory. That is evidence for studying title-supplied memory, not verification of the callback ABI, allocation rules, or placement behavior across console versions.
- Leonida's `docs/d3d12_vulkan.md` §3.4 (D3D-329) reports 32-bit bases and static T#/S# offsets in a shader census. This is evidence about those shaders' GPU-side inputs, not a CPU guest VA limit or a universal API stride. Leonida's `docs/d3d12_xs_surface.md` §9 does not report a measured API increment; XCL's `HANDOFF.md` describes the view and sampler increments used by its compatibility layer. This model takes the guest VA window, base alignment and stride explicitly and does not assign implied values by heap kind.

Only factual observations were taken from the GPL-licensed reports. The Rust implementation and numeric fixtures are original.

### Static retail cross-check

Coordinated with the D3D12 ABI investigation and checked the local retail PE (SHA-256 `e95020b2fa4a721db3df59fdecf75621730ac559d8835252f6c3b658d5a08993`) by static disassembly only. The locations below are RVAs:

| Location | Caller observation |
| --- | --- |
| `0x5a54712`, `0x5cabb3c` | Two callers of wrapper `0x1cf3280`: the former passes zero in R8; the latter forwards its own first argument in R8 and divides its second argument by the device slot-15 return to compute R9. |
| `0x2478e9d`–`0x2478eb5` | The upstream call takes the expected base from title global `0x75df188` and the sum of two stored lengths. See the [backing trace](#backing-and-placed-heap-handoff) for their provenance. |
| `0x1cf32a7`, `0x1cf32be`–`0x1cf32dd` | The wrapper saves incoming R8 in RBX, calls device slot 15 (`+0x78`) using the first dword of the descriptor as the type argument, and records the supplied base alongside the product of the return value and incoming R9. The caller arithmetic is consistent with a descriptor increment; no numeric increment is recovered. |
| `0x1cf3332`, `0x1cf32fa` | For a nonzero supplied base, a helper links a record containing a pointer to that base/size pair before device slot 14 (`+0x70`, `CreateDescriptorHeap`-shaped call with the heap IID at `0x61e0628`). The base is not an extra direct argument to slot 14. |
| `0x1cf3358`–`0x1cf336c` | The success path consumes the slot-9 (`+0x48`) return in RAX and traps on mismatch with the supplied base, but only if the supplied base is nonzero. |
| `0x1cf3392`–`0x1cf3398` | A flag-gated slot-10 (`+0x50`) call returns in RAX; the caller stores its difference from the slot-9 value, rather than requiring the two to match. |

This corroborates a title-supplied expected base on one path. It does not establish a universal heap-placement rule or how a GPU address relates to the CPU VA.

### Backing and placed-heap handoff

The existing terminal slot-15 trace at `05c5ff32` captured raw selector `0` and counts `0x20000`, `0x30000`, `0x8000`. It did not return an increment, allocate descriptor backing, or resume the caller. Everything that follows is static evidence from the same pinned image, not observed execution.

1. **Size the reservation.** At `05c5ff18`–`05c5ff81`, the title adds the first two counts as dwords and independently multiplies that sum and the third count by the zero-extended slot-15 return `s`. With the captured inputs, the two byte spans are `A = round64KiB(0x50000 * s)` and `B = round64KiB(0x8000 * s)`. At `05c5ffc1`, the caller passes five byte lengths `A, B, C, D, E` to `01e86440`. Define `round64KiB(x) = (x + 0xffff) & ~0xffff` in qword arithmetic. `C = pick(dword[0a943914], 0x20) * round64KiB(pick(dword[0a943910], 0x40000))`, where `pick(v, default)` takes `v` if nonzero; both defaults would give `C=0x800000`. `D = round64KiB(qword[0a943918])` and `E = round64KiB(qword[0a943920])` (broadcast add constant `0xffff` from `0615c228`, then clear each low word). None of `s`, the overrides, or the resulting byte lengths was measured.
2. **Preserve the reservation base.** `01e8649a` requests `XMemVirtualAlloc(NULL, A+B+C+D+E, 0x42000, 7, 1)`. On non-null return, `01e864ac` stores that exact `RAX` at `075df188`; `01e864b3` stores `A+B` at `075df190`. Four `VirtualFree` calls (IAT `06793a70`, sites `01e864cd`, `01e864fa`, `01e86531`, `01e8655e`) pass each of A through D's base and length with flags `0x8002` to split off those regions, and five [fixed-base replacements](xmem-boot-abi.md#virtual-allocation) follow in A-through-E order. The caller tests the replacement returns for null but continues to use the original partition bases.
3. **Back the partitions.** `01e866e4` requests the sum of the five 64 KiB page counts in one `XMemAllocatePhysicalPages` call (`0x280`). The caller checks nonzero `EAX` and an unchanged qword count, retains a copy of the tokens at `075df180`, and sends consecutive token slices to [XMemMapPhysicalPages](xmem-boot-abi.md#physical-pages) in **D, E, A, B, C** order (`01e86738`, `01e86760`, `01e86784`, `01e867ac`, `01e867d1`). Each call uses its original partition VA and tests full `RAX` for nonzero. Device [slot 133](xbox-d3d12-abi.md) at `01e8684c` takes the C base and puts `C+D+E` in the description's span field; this resource-shaped call covers the suffix, not the descriptor-heap creation call below. The static teardown at `024730e9`–`02473133` issues null-array unmaps in E, D, C, A+B order and frees the retained tokens; `024731a2` releases the original base with `(base, 0, 0x8000)`.
4. **Request the placed heap over the prefix.** On helper success, `05c5ffd8` stores `C` at `075df168`. `02478e9d`–`02478eb5` passes `075df188`'s value and `A+B+C` to `05cabb00`. The helper calls slot 15 with selector `0` at `05cabb18`, then divides the byte span by the zero-extended result at `05cabb25` (zero would fault; no remainder check). `05cabb3c` passes the quotient and original base to `01cf3280`, with selector `0` and flag `1`. The wrapper writes the quotient's low dword into the slot-14 descriptor at `01cf32aa`, but uses the full quotient times a fresh slot-15 result for its base/size pair. The caller's input span is the prefix, which overlaps the slot-133 suffix at C; exact heap coverage would also require agreement between increments and no count truncation or remainder. On successful slot 14 the caller requires heap slot 9's full `RAX` to equal the saved base and, with this flag, stores slot 10's delta from it.

**Scoped title hook.** For a nonzero base, `01cf3332` links a node for callback `05eb2730`, the stack base/size pair, and the context returned by `04de8620`. It unlinks the node at `01cf3343` after slot 14, before testing that call's status. The first qword of the pinned title's `__XMemAllocationHooks__` export (`06844380`) points to `04deb420`, which jumps to dispatcher `04deb430`. The dispatcher uses flag bits 16–23 as a bucket index; bucket `0x80` selects the same list head (`06843770`) the wrapper updates. It includes nodes with a matching context (or wildcard `-1`). `05eb2730` returns the saved base only if the low 14 flag bits equal `4` and the requested size equals the saved size; on mismatch it delegates to the next callback. This identifies a static path from the title's exported hook to the wrapper's record, not a measured D3D12 call into the hook or a general allocation-hook contract.

The descriptor reservation is not the [separate 64 KiB bump arena](xmem-boot-abi.md#64-kib-bump-arena-static-contract-and-owned-cpu-proof) or a host descriptor heap. Neither an isolated CPU alias nor the owned sizing fixture below establishes the title's GPU placement, coherency or native descriptor encoding.

### Exact reserve and map calls

`05f3fcc0` only jumps through `xmem.dll!XMemVirtualAlloc` IAT `06793a58`; it does not supply a default protection. `01e8649a` explicitly passes protect `1` as the fifth dword. Let `p` be its returned base and `nX = X >> 16` for each byte length X above. The fixed replacements all pass type `0x20406000`, attributes `0x27`, and the protect dword listed below. Their bases also serve as the map destinations.

| Region | Base | Replacement site / protect | Map site | First token index |
| --- | --- | --- | --- | --- |
| A | `p` | `01e8659e` / `0x1004` | `01e86784` | `nD+nE` |
| B | `p+A` | `01e865d0` / `0x1404` | `01e867ac` | `nD+nE+nA` |
| C | `p+A+B` | `01e86600` / `0x8404` | `01e867d1` | `nD+nE+nA+nB` |
| D | `p+A+B+C` | `01e86630` / `0x2404` | `01e86738` | `0` |
| E | `p+A+B+C+D` | `01e8666c` / `0x2004` | `01e86760` | `nD` |

`01e866e4` (return `01e866e9`) calls thunk `05f3fcd0` → IAT `06793a10` with `ECX=0x280`, `RDX=&qword(nA+nB+nC+nD+nE)`, `R8=stack token array`. The first map at `01e86738` (return `01e8673d`) calls thunk `05f3fce0` → IAT `06793a40` with `RCX=p+A+B+C`, `RDX=nD`, `R8=&stack_tokens[0]`. The remaining four calls advance this same stack pointer by 8 bytes per consumed token. The retained `075df180` copy is for teardown, **not** the source of the map calls. This is a fresh allocation, not the [earlier 710 MiB pool](xmem-boot-abi.md#measured-pool-and-static-consumers) at `075eaee0`. The first successful map backs D only; the remaining four regions are mapped on the static success path before #133 and thus before #14. These calls do not establish Xbox CPU/GPU access rights for the raw protection words, and reserve/replacement alone does not prove bytes are accessible.

### Direct guest access after heap creation

`02478f30`–`02478f3c` passes the sum of the first two count dwords to `0555e340`. This helper reserves that many slots from the just-created heap state at `075e7378`, saves its heap pointer and subrange base at `075e74e0/075e74e8`, and **writes directly to the first dword of every stride-spaced slot** (`0555e391`–`0555e3c2`): next-index links followed by `0xffffffff`. The first startup pop (`02478faf` → `0006de60` → `055ac240`) directly loads the next-index dword at `055ac280` from that same subrange. This requires writable CPU bytes at the actual placed VA, not just handle arithmetic. The dword is title freelist metadata while the slot is free, not proof of native descriptor encoding. Startup then submits selected slot VAs to device #18 (`00164efb`) and executes `CLWB` at `04ecc84a` across cache lines intersecting a slot-sized range, using the cached raw-type-zero increment at `075e7000`. This is a cache-maintenance requirement to audit separately, not a demonstrated GPU visibility result. Downstream `0022f700`–`0022f70a` subtracts the cached #9 base and shifts by five to form an index, evidence of a 32-byte indexing assumption in that path, not a measured #15 return or proof of a universal stride.

## Model contract

- A registry tracks one caller-specified, nonempty, non-null guest VA window. A registration claims the exact half-open interval `[base, base + count * stride)` in that window. These are model policies, not documented console restrictions.
- Count, stride and alignment must be nonzero; the base must meet the supplied alignment. The product and exclusive end are checked in `u64`. The whole stride is reserved, including any padding. Live registrations must not intersect; adjacency is allowed. Validation failures do not change the registry.
- Slot `i` is the `i`th stride-wide range starting at `base + i * stride`. Address lookup accepts a slot start, not an interior byte. It queries only the current registrations: a bare numeric VA has no lifetime information.
- Model heap and slot tokens carry an opaque registration identity. Explicit unregister makes them stale even if the exact VA and geometry are later reused. Tokens from another registry are rejected, and dropping tokens does not unregister a heap. These rules do not model COM reference counting.
- The registry checks its own intervals only. It neither consults the launcher VM nor verifies page ownership, commitment or accessibility. The model has no descriptor bytes, host pointers, GPU handles, memory backing, provider registration, title execution or D3D12/HRESULT results.

Run `cargo test --test title_descriptor_heaps`; both the model and its original fixtures live under `tests/`.

## Owned backing fixture for the startup sizing inputs

The bounded terminal probe at device slot 15 (saved return `0x5c5ff32`, outer return `0x2478e27`, full raw heap type zero) captured three dwords: `0x20000`, `0x30000`, and `0x8000`. It did not return an increment. The pinned caller adds the first pair as dwords, multiplies the resulting count and the third dword separately by the zero-extended increment, then rounds each span up to 64 KiB. A later caller divides its backing span by a fresh slot-15 result; its placed-heap wrapper multiplies the count by another slot-15 result. As traced above, the later byte input includes a third region in addition to the two sized by the initial increment.

`cargo test --test owned_descriptor_backing` reuses the interval registry in a separate fixture with one contiguous host allocation of 64 KiB-aligned pages and two adjacent logical regions. The exact placed CPU start of each region is the address of its actual first byte; placement rejects a mismatched supplied base, even another aligned one. The fixture treats the addresses as integers for lookup and resolves them to checked slice indices, never casts a handle back to a pointer. An **owned policy** of 32 opaque bytes per slot produces `0xa00000` and `0x100000` bytes (320 Ki slots and 32 Ki slots), totaling 11 MiB. Both aligned spans divide exactly and multiply back to the original bytes. A policy of 16 also fits the measured inputs, so the arithmetic does not establish a unique increment. The fixture rejects dword carry rather than reproducing the caller's wrap and checks exact division, combined size, placement, and allocation bounds. Placement, lookup, and byte access check the full raw heap kind against type zero. Byte access also requires a live token from this backing's registry. A full-allocation comparison verifies that writes preserve adjacent bytes across page and region boundaries. Foreign owner tokens and stale tokens from a previous registration at the same CPU base are refused.

This fixture does not map guest pages or expose host addresses to the title. The two logical region registrations are test policy, not a recreation of title placement. The static audit above verifies direct freelist dword access in the placed range, but the bounded terminal capture never reaches it. Live placement/allocation, native descriptor layout and lifetime, and the relation of CPU addresses to GPU handles remain unverified. The opaque fixture records are neither native shader descriptor bytes nor a Metal argument-buffer layout. No runtime slot-15 return is implemented.

## Owned software descriptor-handle namespace

**Observed stop (separate scratch run):** heap slot 9 at saved return `01cf335b` returned the full placed CPU base (`0x170600000`). The same heap reached slot 10 at saved return `01cf3395`, with that CPU base echoed in R14 and the raw flag `1` in R15. The probe stopped without returning a GPU handle or resuming. On the *static* success path, the next device call is a live-use slot-15 stride query for raw type `1` (saved return `01cf32c1`, callers `05a54717` / `02478ee2`). Its stride and backing are unverified; the earlier discarded type-1 result does not establish a stride.

**Static consumers in the pinned image:** `01cf339e` stores `GPU_start − CPU_start` as a qword at `075e73b0`. At `000321d8`, `0248c418` and `0248c7d8`, the title adds that delta to a CPU descriptor allocation after passing the CPU address to a descriptor-writing helper. It caches the full result. When inline command space is unavailable, list calls at `000321ff` (slot 36) or `0248c465` / `0248c825` (slot 35) take the full qword in R8. The inline branches bypass these calls and write only its low dword as the second dword of an eight-byte command record (`00032286`, `0248c44e`, `0248c80e`); cached replay also writes the low dword. The second flag-set heap has a separate delta. The startup translation at `075e7010` is instead a difference between CPU addresses of two type-1 heaps. The audited command paths establish a width constraint, not a GPU dereference, native descriptor aperture, first executed consumer, or queue submission.

Run `cargo test --test owned_descriptor_handles` for the arithmetic-only proof. It exhaustively round-trips every slot in a synthetic 38 MiB placed range (`0x130000` slots at 32 bytes) and an independent 128-slot range with a distinct synthetic stride. Each address is a number, not a pointer. Checked offset translation pairs `CPU_base + i * stride` with `software_base + i * stride`. Nonzero aligned bases, checked half-open bounds and disjoint reservations give distinct full-width handles. The fixture admits only software ranges whose last byte fits `u32` (an exclusive end of `2^32` is allowed). It proves all admitted handles round-trip through one low dword and rejects a high-bit value that would alias an admitted handle if truncated.

Decoding requires an expected heap key with namespace owner, generation and epoch; raw bits do not carry that context. Retirement invalidates the key and reserves its software range against reuse until an explicit epoch advance with no live heaps. A recycled value with the new key necessarily decodes as the new slot in **both** widths; a real epoch transition would also require proof that no old raw users remain. The fixture only enforces the local no-live-heaps condition. It exercises foreign owners, stale generations/epochs, wrong heaps, interior and one-past addresses, arithmetic overflow, and overlaps.

This test does not allocate or alias descriptor bytes, implement a heap method or any command record, validate descriptor encoding or synchronization, or model hardware address units or a native GPU aperture. A CPU VA or a Metal buffer's `gpuAddress` is not a substitute. The slot-10 stop remains in place; neither feeding a synthetic value to the title nor executing or submitting packets is part of this proof.

## Independent CPU backing for the two raw-1 heaps

**Observed only in the bounded scratch diagnostic:** after the first placed heap's software-only #10 result, the title reached live-use raw-1 #15 at `01cf32c1`, with count `0x80`, next owner `075e73c0`, zero placement input, and initialized words `(1,0x80,1,1)`. The first placed heap's stored delta and CPU limit trim to A+B checked out. The diagnostic stopped without returning a stride; nothing below this gate was observed in that run.

**Static successor:** the wrapper zero-extends EAX into R12, calls the title TLS/context helper `04de8620`, then multiplies the count by this stride and stores the placement pair `{0, 0x80 * stride}`. Zero RBX skips the placed allocation hook. At #14's call (`01cf32fa`, saved `01cf32fd`), define S as the address of the saved return qword. The wrapper allocates `0x50` bytes after seven pushes, so `[S+0x90]` is the helper return `05a54717`; the helper's `sub rsp,0x28` and call put the original top return `02478ee2` at `[S+0xc0]`. The call puts `S+0x38` in RDX (16 initialized descriptor bytes), sealed image RVA `061e0628` in R8, and `S+0x30` in R9 (output); the pair is at `S+0x48/+0x50`. For a future terminal capture, validate the canonical device and original top slot, the full frame and computed pointers, and read only the bounded initialized descriptor/pair and pinned IID. Check the output address against its computed stack slot without reading or writing its pointee. Stop there, before any heap is published.

**Later static uses:** the first `(1,0x80,1,1)` heap and the second `(1,0x80,1,0)` heap (`075e7408`, outer `02478efc`) both have zero placement input. Their #9 results are full CPU addresses. The wrapper saves CPU base, `base + count * returned_stride`, and stride in each owner. The first also calls #10 and saves its *own* delta; the second does not. Bump allocation (`0156c240`) multiplies by owner stride and bounds-checks the end, with alignment argument 1 for these two startup suballocations, not a measured native base alignment. The second heap's freelist initializer steps by owner stride and writes a dword at each slot start (`01f76f88/99`), implying suitably aligned, writable CPU storage throughout the span, not a hardcoded step of 16 or 32. In particular, the later #9 saved at `02478f5d` reloads the **placed** heap from `075e7390`, not the first raw-1 heap. `02478f85` separately allocates the first raw-1 heap's 128-entry run; `02478f9d` records the full CPU difference between that suballocation and the second raw-1 heap's base. This is not either GPU delta. The optional device #24 path at `04ecc864/87e` adds that CPU difference before the call, without an observed low-dword narrowing there. The known low-dword command writes above involve the **placed** delta, not proof of packed sampler stride, aperture, or binding. The known teardown path ultimately calls heap Release (slot 2).

The two candidate strides are **modeled policies**. XCL's compatibility layout uses 16 bytes for samplers; Leonida proposes 32 (16 bytes plus padding) pending an actual console value. Neither establishes native stride, and the audited pointer stepping uses the returned value, not an independent constant. Both model geometries can supply CPU-only backing for the narrow startup shape; neither justifies returning a stride in the title or exposing native sampler bytes.

Run `cargo test --test owned_type1_backing` on macOS. The fixture tests both 128-slot geometries (logical spans `0x800` and `0x1000`), separate flagged and CPU-only roles, and an unrelated owner. Each gets an independent anonymous RW/NX page with two no-access guard pages, verified for both current and maximum protections. The entire host page is usable only by the test oracle; the heap's checked slot access excludes page padding. Tests cover endpoint writes, canaries, isolation, wrong role/owner, stale IDs, alignment, and one-past bounds. Failed publication unmaps the staged range without disturbing live heaps. Retirement immediately invalidates the key, but a retained lease keeps the backing mapped until its actual last drop. The fixture does not recycle staged IDs or admitted CPU starts, even though the kernel is free to reuse an unmapped address. This proves host mapping and ownership only: no guest pointer publication, slot return, GPU handles, sampler encoding, Metal descriptor creation, or command work.
