# Title shader specification and ahead-of-time Metal roadmap

**Scope.** Aim for every shader and reconstructible pipeline of a pinned title build on an explicitly supported Metal device/OS profile. Do not promise that the current extraction contains every shader the title can create at runtime, or that Metal can represent every Xbox operation directly. Track offline coverage of shipped inputs and runtime coverage of observed creation requests separately. A fallback must be explicit and validated; an unsupported request is not a cache hit or a translated shader.

## Goal 1: document the title's shader and pipeline formats

Start with an evidence ledger, not a single unified format. The local extraction contains **26,503 wrapped DXBC records**, **26,698 native FSSM payloads**, and **21,522 compiled-library programs**; these are separate denominators, not a count of unique shaders. The current [native compute census](compute-reachability.md) validates 2,689 compute spans. DLL-embedded shaders and runtime-created inputs are separate inventories, not covered by those numbers.

| Surface | What to document and verify |
|---|---|
| Wrapped records | Record framing and compression; DXBC sections, versions, shader signatures/validation data, `NOBC` versus genuine DXIL; XDAT directory, XBCH native variants, and stage provenance. |
| FSSM native programs | Versions, extents, padding versus code, possible multiple entries, compute/graphics metadata, resource/register setup, wave width, bindings, status bits, flags and unknown sections. Distinguish container headers from the ISA and from pipeline-supplied state. |
| Library and FSPX programs | Compression and table boundaries, program/blob indices, variant and digest relationships, FSPX/stage records, dependency links and references; prove whether links identify related source or byte-equivalent code. Do not treat extracted `.code` files alone as pipelines. |
| DLL and runtime inputs | Inventory those separately; classify native/DXIL forms, dynamic shader and PSO creation, specialization or patching, and inputs that the existing extraction cannot recover. Do not infer completeness from filenames or magic alone. |
| Dispatch, linkage and PSOs | Root and descriptor layouts, user SGPRs, stage I/O, local/group inputs, graphics linkage, fixed-function state, formats, samples, blending, depth/stencil, and dynamic versus baked state. Record which values come from a shader, another linked stage, a library table or a runtime request. |
| Xbox RDNA dialect | Compare explicit LLVM targets, AMD/Mesa references, XCL/Leonida behaviour and owned fixtures. Record operand forms, literal and extension words, implicit state effects, wave semantics and precise divergences. A successfully decoded instruction is not evidence of correct semantics. |

For each version and field, record width, offset or encoding rule, units, reference base, bounds/overlap checks, and evidence level (*observed*, *inferred*, *verified by fixture*, *unknown*). Keep per-source and per-stage coverage and tell absent data apart from fields not yet interpreted. Close this goal when every observed family is documented with checked extents and joins, or has a specific named blocker rather than guessed semantics. Commit specifications, tests, and aggregates only; treat all local inputs as read-only. No shader assets, payload listings, private indexes or generated Metal files in Git. GPL references inform facts, not implementation.

## Goal 2: build a verified translator and local precompiler

1. **Normalize inputs.** Validated parsers produce a versioned module plus an explicit dispatch/resource/linkage contract. Select a verified encoding profile; never pick the dialect that merely prints more instructions. Strip padding and use a checked reachable CFG. Unknown PC targets or encodings stop with specific diagnostics.
2. **Lift into typed Rust IR.** Model scalar/vector registers, wave masks, control flow, resource accesses, synchronization, memory order, FP modes and stage exports. Prove a feature with an owned fixture against a CPU oracle and Metal readback, plus a native AMD or other independent oracle where available. Distinguish parser, decode, IR, lowering, compilation, pipeline creation, and execution failures. A shader that merely compiles is not validated for output equivalence.
3. **Lower by capability.** Establish compute first, then linked vertex/pixel render pipelines, then harder stages and features such as geometry, mesh, BVH, and wave64. When Metal lacks a direct equivalent, require a tested alternate lowering or report the exact device/backend limitation. Treat genuine DXIL as its own front end; never feed `NOBC` to a desktop DXIL path. Keep stage linkage, descriptor interpretation and memory behaviour explicit.
4. **Enumerate and bake locally.** Build a manifest from parsed shipped program and PSO records, actual stage variants, specialization and concrete pipeline state. Canonicalize and deduplicate translated modules separately from pipelines. Generate MSL, compile Metal libraries, then create compute and render pipelines using the available device/OS APIs. Populate Metal binary archives where supported, and verify cache hits with real pipeline creation. Keep artifacts in a local cache outside Git, never in the source archives.
5. **Use stable cache keys.** Include pinned title/build identity, canonical module/variant and linkage/ABI, translator and IR/profile versions, shader compiler options, specialization and the full baked PSO state. Device capability, GPU and relevant OS/toolchain identity must gate compiled artifacts. Validate on load, and rebuild or report clearly on mismatch. Do not assume portable binary archives across machines or system updates.
6. **Reconcile at runtime.** Exact requests reuse precompiled artifacts. Measure hits/misses and classify misses (new program, dynamic state, specialization, unsupported feature, stale artifact). Where correct and permitted, translate/compile uncached requests locally and persist with the same key; otherwise report a specific unsupported reason. Do not fabricate PSO combinations or silently replace effects with no-ops.

### Gates and immediate work

* **Next specification milestone:** bounded parser + cross-reference ledger for the extracted library's program/blob/PSO records, tied to owned tests; independently specify the smallest reachable compute candidate's operand forms and user-data bindings. Start translating verified compute slices before the whole graphics specification is complete.
* **Next translator milestone:** combine the owned wave32 `CMPX`/`EXECZ` path and checked descriptor/store path. Test exact output and inactive-lane preservation, explicit waits, invalid descriptors and bounds on CPU and Metal. Then bake and load an owned compute artifact using the same cache contract planned for the title.
* **Coverage gates:** report by source and stage: inputs inventoried, validated, linked, lowered, Metal-compiled, pipeline-created, and execution-verified where applicable; report local cache outcomes for each observed request. No unknowns removed from the denominator. The precompiler goal covers all reconstructible shipped PSOs on the target Metal profile; the broader translator goal also requires runtime-created variants or explicit measured blockers. Do not promise 100% before both gates have evidence.
